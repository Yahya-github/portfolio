# Phase 4 — UI Design Contract

> Visual and interaction contract for the horizontal pager: the sliding track, every input device, URL and history, overflow at the page edge, focus, the live region, the Phase 4 stand-in for the letters, and the `?debug` tuning overlay. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This phase adds **motion and input only**. It adds no new type size, colour, spacing value or page composition. Every visual token is inherited from the approved `03-UI-SPEC.md` and `styles/tokens.css`. One token is added (`--ease-retarget`, below). Pages look exactly as in Phase 3 at rest; the label letter-gap fix is the one visible change at rest.

**Sources, in priority order:** `docs/superpowers/specs/2026-11-03-portfolio-design.md` rev 5 (§5 Motion, §6 Navigation and paging, Decisions 3 and 4; wins over everything), `04-CONTEXT.md` D-01 to D-14 and folded todos (locked), `03-UI-SPEC.md` (approved, all tokens and the shell markup contract), `.planning/research/SUMMARY.md` and `PITFALLS.md` (pitfalls 1-3), REQUIREMENTS.md (NAV-01..04, NAV-07, A11Y-01), ./CLAUDE.md. No phase RESEARCH.md exists. Every "Claude's discretion" item from 04-CONTEXT is decided below and marked **(decided here)**.

**Not in this phase (do not build):** letters-to-rail FLIP glide, rail name reveal on hover, first-visit hint, opening animation, custom cursor, Pause motion control, full reduced-motion pass (Phase 5); decorative devices, previews, walkthrough, phone portrait layouts (Phase 6).

## Motion Tokens

Inherited: `--dur-page: 600ms`, `--ease-page: cubic-bezier(0.77, 0, 0.18, 1)`, `--dur-ui: 150ms`, `--ease-ui: cubic-bezier(0.16, 1, 0.3, 1)`; all `--dur-*` are 0ms under `prefers-reduced-motion: reduce`.

Added to `tokens.css` **(decided here)**:

| Token | Value | Used for |
|-------|-------|----------|
| `--ease-retarget` | `cubic-bezier(0.3, 0.6, 0.18, 1)` | A slide that starts while the track is already moving (retarget, D-01). It starts with velocity instead of from rest, so the track never stalls when the visitor presses again; it lands with the same deceleration as `--ease-page`. No control point above 1 (design doc §5 ban list). Tunable in device tests; keep y-values in [0, 1] |

Motion rule (design doc §5, binding): horizontal, fast, decisive, no bounce, no overshoot, only `transform` and `opacity` animate, everything is interruptible and retargets, never queues.

## Track Contract

### Layout (JS on)

- `html[data-js]` is set by an inline script in `<head>` before first paint (the hook name already exists in `shell.module.css`; Phase 4 adds the script). Every rule below applies only under `html[data-js]`; JS-off rendering stays exactly as Phase 3 (one page per route, `.page[inert] { display: none }`).
- `main#content` becomes the track: `display: flex; width: calc(6 * 100vw); transform: translate3d(calc(var(--track-index) * -100vw), 0, 0)`; `will-change: transform` only while sliding (removed on landing).
- Each `.page` is `flex: 0 0 100vw` and keeps its Phase 3 box (desktop `height: 100svh; overflow-y: auto`, phone `min-height: 100svh`, document scroll). Inert pages stay rendered (the Phase 3 `display: none` rule is overridden under `html[data-js]`).
- `html, body`: `overflow-x: clip; overscroll-behavior-x: none` (stops Chrome / Safari horizontal history swipe and horizontal rubber-band, D-04). Desktop pages add `overscroll-behavior-y: contain` so inner scroll never chains to the document.
- Phone (`<= 820px`): `touch-action: pan-y` on the track (vertical scroll stays native; horizontal swipes are ours).
- **First paint:** the server renders `--track-index` for the route on `main` (as Phase 3 does for `--page-index` on the progress bar), so a deep link to `/projects/` paints Projects in place. No slide, no transition, no flash of Index on load. Transitions are enabled only after hydration.

### Slide

| Case | Motion |
|------|--------|
| From rest to any page (one step or a jump) | `transform` over `--dur-page` (600ms) with `--ease-page`. Distance never changes the duration (D-03): 01 → 04 crosses 02 and 03 in the same 600ms |
| New intent while sliding (retarget, D-01) | Start from the track's **current rendered position** (read it, never snap to the old target), slide to the new target over a fresh 600ms with `--ease-retarget`. Relative intents (+1, -1) apply to the **current target**, absolute ones (Home/End, letters, Next, Back/Forward) replace it, so → → fast lands two pages on. An intent that resolves to the **same in-flight target** (e.g. Home pressed twice, or End while already sliding to 05) is a no-op: no restart, no new "slide started", no chrome, focus or history change |
| Ends (D-02) | On 00 a "previous" intent and on 05 a "next" intent do nothing: no movement, no nudge, no rubber-band, no announcement. Only "Back to the start" (and Home, the letters, Back) return from 05 |
| Reduced motion | Instant: the track jumps to the target (0ms) and the landed signal fires in the same frame. Listen to the `(prefers-reduced-motion: reduce)` media query **live** (`change` event, WR-08), not once at load |

The pager exposes two signals for Phase 5 (cursor and FLIP): **slide started** (from, to, source) and **landed** (index), plus the track's resting position for an index. A retarget emits a new "slide started"; only the final arrival emits "landed".

### Progress bar (D-11)

- The footer's 2px ink bar animates with the track: `transform: translateX(calc(var(--track-index) * 100%))`, same 600ms, same curve (`--ease-page`, or `--ease-retarget` on a retarget), same start instant. It never runs ahead of or behind the track. Transform only, never `width` or `left`.

### Chrome during the slide (D-10)

At the instant a page change is decided (within one frame of the input, well under 100ms), before the track moves, these switch to the **target** page, and switch again on every retarget:

| Element | Change |
|---------|--------|
| Header cols 4-6 | "Index" or "0N Section" for the target |
| Footer counter | "0N / 05" for the target (tabular, no animation) |
| Footer Next | "Next, {Section after target}" with that href; on 05 "Back to the start" to `/` |
| Rail current letter | accent + `aria-current="page"` move to the target's letter; its vertical "0N Section" name changes with it |
| Header "Say hi" `aria-current` | on when the target is 05 |
| `document.title` | the target route's metadata title (`lib/metadata.ts`), e.g. "Projects, Yahya Hallani"; "Yahya Hallani" on Index |
| `inert` and heading level | the target page drops `inert` and its title becomes `h1`; every other page is `inert` with an `h2` title |

These are text and attribute swaps, never animated.

### Letters stand-in (D-09; Phase 5 replaces it with the FLIP glide)

- **Leaving Index (00 → any):** the hero-mode YAHYA row (with its captions) moves with the Index page as if printed on it: same translateX as page 00, same 600ms, same curve, same start instant, so it exits left in one piece with the page. The rail is not shown during this slide. **On landing**, `LetterNav` switches to `data-mode="rail"` and the rail fades in: `opacity` 0 → 1 over `--dur-ui` (150ms) with `--ease-ui`. No letter moves or scales; nothing flashes at the hero position.
- **Hidden means unreachable:** whenever the rail is not shown it is `visibility: hidden` (plus opacity 0 and `pointer-events: none`), never opacity alone, so its letter links cannot be tabbed to or read. On landing off 00, `visibility` turns visible at the start of the 150ms opacity fade. While the hero row rides **out** with page 00, `LetterNav` is `inert` (the row stays visible but cannot be focused); it is live again once the rail appears.
- **Returning to Index (any → 00):** at slide start the rail hides at once (`visibility: hidden`, opacity 0, no transition), `LetterNav` switches to `data-mode="hero"`, and the row starts from page 00's current offscreen position and rides in with the page.
- **Retarget across Index** (e.g. 01 → 00, then → again before landing): the row follows page 00's offset continuously; the rail only appears on a landing that is not 00.
- Between pages 01-05 the rail stays fixed and still; only the current letter's accent and name change (above).
- Reduced motion: mode switch and rail appearance are instant.
- The hero row's resting position is measured against the track's resting position, never its in-flight one (design doc §6 v7 bug note), so paging back mid-slide still lands it exactly on its Phase 3 position.

### Overflowing pages (NAV-07, D-05, D-06, D-07)

- A page "overflows" when its scroll height exceeds its client height by more than 1px (200% zoom, short screens).
- **Desktop wheel:** a vertical-dominant gesture on an overflowing page scrolls the page natively (the listener does not `preventDefault`). The gesture that brings the page to its bottom (or top) is spent: its momentum never pages. Only a **new gesture that starts while the page is already at that edge**, in the edge's direction, pages. A horizontal-dominant gesture pages at once at any scroll position (pages have no horizontal scroll).
- **Keys on an overflowing page (decided here):** Space, Page Down, ↓ scroll the page (native behaviour) and page "next" only on a fresh press made at the bottom edge; Shift+Space, Page Up, ↑ mirror that at the top. ← / → always page. Home / End always jump to 00 / 05. A held key (auto-repeat) that reaches the edge stops there; it never pages through the edge.
- **Pages always open at their top** (D-06): the target page's `scrollTop` is set to 0 at slide start, before it is visible. No remembered positions, forwards or backwards.
- **Phones (D-07):** vertical movement only ever scrolls the document; reaching the bottom never pages. At slide start the window scroll resets with `window.scrollTo(0, 0)` (instant, not smooth); so the outgoing page does not jump, it is held in place with `translateY(-{previous scrollY}px)` for the duration of the slide, then cleared on landing.
  - **Retarget back to the held page** (e.g. 02 → 03, then ← before landing on 03): this is a cancelled leave, not an arrival. The hold stays on while the track slides back; on landing, in one frame, the `translateY` is cleared and `window.scrollTo(0, {previous scrollY})` restores the scroll, so the page ends exactly where the visitor left it with no visible jump. This is the one exception to D-06 (the visitor never left the page). Its focus and live region follow the normal landing rules.
  - Only one page is ever held: a chained retarget to a third page keeps the original hold until landing, then clears it.
  - **Collapse strictly after landing:** the rule that sets non-current pages to `height: 100svh; overflow: clip` (so the document's scroll length follows the current page only) is applied only after the "landed" signal, never during a slide or a retarget; during a slide every page involved keeps its full height. Under reduced motion "after landing" is the same frame as the change, still in this order (hold/scroll reset, change, then collapse).

## Input Contract

One state owner; inputs emit intents only (`next`, `prev`, `goto(index)`). Starting values below are **decided here** and are tuned on the D-12 devices and the D-13 traces; tuned values are recorded in VERIFICATION.

### Wheel and trackpad (NAV-01, D-04, IN-01)

| Rule | Value |
|------|-------|
| Listener | one non-passive `wheel` listener on the window; `preventDefault` only when the gesture pages or would page (so native inner scroll and pinch still work) |
| Pinch-zoom | `ctrlKey` wheel events are ignored and never paged (trackpad pinch) |
| Delta normalisation | `deltaMode` 1 (lines) × 16px, `deltaMode` 2 (pages) × viewport height |
| Axis | the dominant axis of the gesture's accumulated delta wins; down / right (positive) = next, up / left = previous. Trackpad swipe right-to-left = next |
| Threshold | page on the first event at which the gesture's accumulated dominant-axis delta reaches **48px** |
| Gesture boundary | a gesture ends after **160ms** with no wheel event; the accumulator resets then (IN-01). After a gesture pages, every further event of that gesture is swallowed, including the momentum tail, however long |
| Fresh flick during a tail | a new gesture is also recognised inside a continuous stream when the per-event magnitude rises again after decaying (at least 2× the running minimum of the last 3 events and above 16px): a deliberate second flick during momentum pages (PITFALLS checklist) |
| During a slide | a new gesture retargets (D-01); the momentum of the gesture that started the slide never does |
| Back/forward swipe | `overscroll-behavior-x: none` on html and body plus `preventDefault` on horizontal paging gestures; verified on macOS Safari and Chrome (D-04) |

### Keyboard (NAV-02, WR-04)

| Key | Action |
|-----|--------|
| → , Page Down, Space | next (Page Down / Space scroll first on an overflowing page, see above) |
| ← , Page Up, Shift+Space | previous (same scroll-first rule) |
| ↓ / ↑ | next / previous on a fitting page; scroll first on an overflowing page |
| Home / End | `goto(0)` / `goto(5)` |
| Held key (`event.repeat`) | walks pages one after another: a repeat is accepted only when the previous step has landed **and** at least **600ms** have passed since the last accepted step (a fixed constant, not `--dur-page`, which is 0ms under reduced motion), so holding → steps 01, 02, 03 … each visibly arriving (decided here). Why 600ms: it is the nominal page duration, so a held key walks at the same rhythm with and without reduced motion; under reduced motion landings are instant, and without the interval OS auto-repeat (~30ms) would cross all six pages in about 200ms, too fast to see the counter or release on the intended page. Fresh (non-repeat) presses always retarget at once |

Never page when:
- **Space** is pressed while a `button`, `a`, `summary` or an element with role button/link has focus (it activates that control, WR-04).
- Focus is in an `input`, `textarea`, `select` or `contenteditable` (none exist now; the guard is for Phase 6).
- Alt, Ctrl or Meta is held (browser shortcuts such as Alt+← keep working).
- The event was already `defaultPrevented` by a component.

### Phone swipe (NAV-03, D-08)

| Rule | Value |
|------|-------|
| Events | Pointer Events (`pointerType: "touch"`); `touch-action: pan-y` on the track |
| Edge exclusion | a touch starting within **20px** of the left screen edge is ignored for paging (left to the system back gesture, Decision 3) |
| Axis lock | after **12px** of movement, the gesture locks horizontal if `|dx| > 1.5 × |dy|` (about 34°), else vertical for the rest of the touch. A vertical lock never pages |
| Commit | on release, page if `|dx| >= 48px`, or `|dx| >= 24px` with velocity `>= 0.3 px/ms` over the last 100ms. Swipe left (finger right-to-left) = next |
| Visual follow | none in Phase 4: the track does not follow the finger; it slides on commit (decided here: one motion path, and no drag-then-snap that reads as bounce). A short or vertical swipe does nothing. **Revisit on device:** item on the D-12 iPhone and Android checklist; if the swipe feels unresponsive without follow, record it in VERIFICATION as a follow-up |
| Cancel | `pointercancel` (the browser took the touch, e.g. for scrolling, the system back gesture or a call) ends the gesture with no page, whatever its distance |
| Ends | swipe "next" on 05 and "previous" on 00 do nothing (D-02) |

### Links that page (in-app navigation)

- Plain primary clicks (button 0, no modifier) on internal links to one of the six routes become `goto(index)`: hero letters, rail letters, footer Next / "Back to the start", header "Say hi", the phone Index section list. The `href` stays a real route.
- Ctrl/Cmd/Shift/Alt-click and middle-click are left to the browser (new tab, etc.).
- Clicking the current page's own link does nothing (no slide, no history entry, no announcement).

## URL and History Contract (NAV-04)

- Routes are the Phase 3 routes with trailing slash: `/`, `/achievements/`, `/projects/`, `/experience/`, `/about/`, `/say-hi/`.
- Deep link: the exported HTML for that route renders that page current and paints it in place (Track contract, First paint).

## Accessibility Contract (A11Y-01, WR-06)

| Rule | Contract |
|------|----------|
| Reachability | At rest only the current page is not `inert`. During a retarget, the page that holds focus stays non-inert until landing (see Focus hand-off), so at most two pages are live for at most 600ms. Header, footer, skip link and live region are never inert; `LetterNav` is inert only while the hero row rides out with page 00, and the hidden rail is `visibility: hidden` |
| Focus hand-off | Focus moves to the new page's title heading (`id="title-{slug}"`, `tabIndex={-1}`) with `focus({ preventScroll: true })` at two moments only: (1) **the first change** of a slide from rest, at slide start, after the heading level swap commits; (2) **landing**, if the landed page is not the one holding focus. Intermediate retargets do not move focus: the page that holds focus keeps `inert` off until landing, then becomes inert in the same frame focus moves to the landed heading. A screen reader therefore hears at most the first heading, the landed heading and the live region, never one heading per retarget. Focus is never left on an element inside an `inert` page (WR-06) |
| Focus ring on headings | Per the 04-CONTEXT discretion bullet: the existing 2px accent ring (4px offset) shows only when the change came from the keyboard. Title headings use `:focus:not(:focus-visible) { outline: none }`, so the browser's `:focus-visible` heuristic shows the ring after a key-initiated change and hides it after a mouse, wheel, swipe or history change. **Exempt:** headings whose content is entirely visually hidden (Index "Yahya Hallani", Projects, Experience, Say hi) never show a ring (`outline: none` on `:focus`), since there is no visible box to frame. **Display-stack headings** (Achievements AC/HI/EV/EM/EN/TS, About TWO/HAB/ITS): the ring goes on the heading element, which is the stack wrapper (`display: block`, its box sized to the stack), at the standard 4px offset; it falls inside the page's padding box (frame-top 72px above, rail column + margin left), so the page's `overflow` never clips it. Every control keeps its 2px ring unchanged. The next Tab goes to the first focusable element of the new page |
| Live region | One `<p>` in the shell, outside `main`, `aria-live="polite"`, `aria-atomic="true"`, class `visually-hidden`. Text set **at landing**, once per landed page (retargets announce only the final page): "{Section name}, page {n} of 6", where n = index + 1 |
| Initial load | Nothing is announced and focus is not moved on first load or deep link |
| Ends | A refused "next" on 05 or "previous" on 00 announces nothing and moves no focus |
| Skip link | unchanged; target `#content` |
| JS off | unchanged Phase 3 behaviour: every page is a normal route |
| axe | zero violations on all six pages at 1440x900 and 390x844, after paging into each page (not only on direct load), in both motion modes |

## Debug Overlay (`?debug`, D-14)

A tuning tool for Yahya's device sessions on the Vercel PR preview. Off by default.

- Present only when the URL has a `debug` query parameter. Its code is a dynamic `import()` loaded only then, so it adds nothing to the default bundle (the 150 kB gzip JS gate stays green).
- Read-only: it changes no pager behaviour, threshold or timing. Without the flag none of it exists in the DOM.
- Placement: `position: fixed; top: calc(var(--frame-top) + var(--space-md)); right: var(--space-lg); z-index: 40;` ground background, 1px `--color-hair` border, padding `var(--space-xs) var(--space-sm)`, `pointer-events: none`, `aria-hidden="true"`. Label role, `tabular-nums`; field names in dim, values in ink; one field per line, `row-gap: var(--space-xs)`. No accent.
- Fields (names from a typed `content/` entry like all copy): "Index" `{current} → {target}`; "Phase" `idle` / `sliding`; "Source" `wheel` / `key` / `swipe` / `link` / `history`; "Wheel" `dx {n} dy {n} mode {0|1|2}`; "Accum" `{n} / 48`; "Gesture" `#{n}` and `open` / `spent`; "Edge" `top` / `bottom` / `none`; "Swipe" `dx {n} v {n}` and `h` / `v` lock; "Motion" `full` / `reduced`. Values update in place; nothing flashes.

## States Inventory (Phase 4 additions)

| State | Treatment |
|-------|-----------|
| Rest (landed) | Phase 3 appearance; one page in view; `will-change` removed |
| Sliding | track and progress bar move together; chrome already shows the target; target page live, others inert; focus on the target heading |
| Retargeting | slide restarts from the rendered position with `--ease-retarget`; chrome and accent switch again |
