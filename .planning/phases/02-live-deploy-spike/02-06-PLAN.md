<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub → Vercel GitHub App | Vercel builds whatever lands on main or a PR branch |
| internet → yahya-hallani.dev and previews | Public, unauthenticated readers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-22 | Elevation of privilege | Vercel GitHub App | mitigate | The app gets access to the `portfolio` repo only (Task 1 step 1), and CI needs no Vercel tokens |
| T-02-23 | Information disclosure | public previews (D-14) | accept | Previews contain only the same public content as the repo, and every response carries `X-Robots-Tag: noindex` (verified on the preview in Task 3) |
| T-02-24 | Spoofing (domain takeover) | DNS | mitigate | The domain is registered and its DNS is managed in the same Vercel account. No wildcard records are added, and the apex is attached directly to the project. |
| T-02-25 | Tampering (downgrade) | transport | mitigate | `.dev` is HSTS-preloaded, and the HSTS header from vercel.json is verified live. The certificate is checked without `-k`. |
| T-02-26 | Tampering (build env drift) | Vercel build | mitigate | `engines.node: 22.x`, plus `ENABLE_EXPERIMENTAL_COREPACK=1` with `packageManager: pnpm@12.11.2`. The versions are confirmed from the build log in Task 1. |
| T-02-27 | Information disclosure | Vercel Toolbar script on previews | accept | Turning it off is optional (Task 1 step 6), and the CSP blocks third-party scripts anyway |
</threat_model>
