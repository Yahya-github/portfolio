# Phase 3 — UI Design Contract

> Visual and interaction contract for the static design system and the six server-rendered pages. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This phase builds `styles/tokens.css`, the 12-column grid, the frame (header, footer, rail, letter nav, skip link) and the final **desktop static layout** of all six pages (03-CONTEXT D-01), with all text from typed data files, working with JavaScript off. Nothing moves in this phase: no paging, no glide, no cursor, no walkthrough, no decorative devices, no colour twins.

**Sources, in priority order:** `docs/superpowers/specs/2026-11-03-portfolio-design.md` rev 5 (approved 2026-11-07; wins over everything), 03-CONTEXT.md D-01 to D-14 (locked), `.planning/phases/01-design-gate/01-UI-SPEC.md` (approved token values), `docs/reference/font-metrics.md` ("Winner"), the approved sketch `docs/reference/swiss-horizontal-v7.html` (reference for measured CSS values and verified copy, not code to copy), `docs/material/links.md`, REQUIREMENTS.md, ./CLAUDE.md. No RESEARCH.md exists for this phase.

**Where design doc rev 5 supersedes 01-UI-SPEC** (applied below; do not use the older value): Achievements is variant (b) with the AC/HI/EV/EM/EN/TS stack; the accent has four uses and rail letters never take the accent on hover or focus (their focus ring is ink); Experience splits 6/6; Projects has five compact rows (MAME first); Say hi links sit in cols 1-6 top-aligned with the address under them in cols 1-3; Index has no proof line; the font is Instrument Sans with `--yahya-fit: 2.188`.

### Font loading contract (Claude's discretion, decided here)

The fitted YAHYA must not shift when the font loads, and it must render with JS off, so v7's `document.fonts` + `.fonts-ready` visibility gate is not allowed in Phase 3.

- `app/fonts.ts`: keep `next/font/local` on the committed variable file, `weight: "400 700"`, `declarations: [{ prop: "font-stretch", value: "75% 100%" }]`, `variable: "--font-sans"`, `preload: true` (default), and change **`display: "swap"` to `display: "block"`**. One 88.7 kB file, preloaded, same origin, immutable cache: the block period costs at most one round trip, and no fallback face ever paints the Poster word at the wrong width.
- `adjustFontFallback` stays on (default) for the block-timeout case.
- Two axes from one file: body text sets `font-stretch: var(--wdth-body)` (100%); YAHYA, rail letters and Display words set `font-stretch: var(--wdth-display)` (75%).
- Poster size depends only on viewport units and `--yahya-fit`, never on measured text, so layout is identical before and after load.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Caption number to name gap, Experience date to role, gap under a Projects row head |
| sm | 8px | Rail letter gap (fine pointer), Projects lead line gaps, Projects row head gap |
| md | 16px | Hero caption offset under YAHYA, header/footer baseline padding, About paragraph gap, Say hi links to address |
| lg | 24px | Grid gutter and margin (desktop), header link gap, Achievements line gap, grid top padding, gap above the footer |
| xl | 32px | Display head to its table, phone block gaps |
| 2xl | 48px | Phone gap between stacked tables and blocks |
| 3xl | 64px | Base of `--hero-bottom-gap` |

Rhythm rule: more space between groups than within. Inside a row `xs`/`sm`; title to list `xl`; between blocks `2xl`. Never the same padding on every element.

Exceptions (all multiples of 4, all named tokens):
- `--hero-bottom-gap` 96px: YAHYA bottom edge to the footer top.
- `--frame-top` 72px and `--frame-bottom` 56px: every page pads by these.
- `--rail-col` 56px / 36px: pages 01-05 pad left by `--grid-margin + --rail-col`.
- `--row-pad` 12px, 8px below 880px viewport height on desktop (Projects and Experience rows, design doc §7).
- Touch: under `(pointer: coarse)` the rail gap is 28px, and every link, rail letter and header/footer control has a 44x44px minimum hit area (padding or pseudo-element) that never overlaps a neighbour.
- Hairline 1px and progress bar 2px are line weights, not spacing.

### Grid

- `.grid` primitive: `display: grid; grid-template-columns: repeat(12, minmax(0, 1fr)); column-gap: var(--grid-gutter);`. Nested blocks use `grid-template-columns: subgrid`.
- Page box: `width: 100vw; height: 100svh; padding: var(--frame-top) var(--grid-margin) var(--frame-bottom); overflow-x: clip; overflow-y: auto;`. Pages 01-05 add `--rail-col` to the left padding. The page's inner grid is `height: 100%` on desktop.
- Every element starts and ends on a column line. Flush left, ragged right. Nothing is centred.
- Breakpoints: desktop `>= 1024px`, tablet `821-1023px` (desktop compositions, same tokens), phone `<= 820px` (single-column stack, D-04).
- Desktop fit: every page fits 1440x900, 1366x768 and 1280x720 without vertical scroll. If content exceeds (zoom, short screens), the page box scrolls vertically. Never horizontal scroll at any width from 320px.

## Shell and Markup Contract (D-05, D-06; mechanics are Claude's discretion, decided here)

Every route renders the same shell, in this DOM order:

1. `SkipLink`: `<a href="#content">Skip to content</a>`.
2. `Header` (`<header>`).
3. `LetterNav`: `<nav aria-label="Sections">` with the five letter links. One set of five elements for the whole site, so Phase 5 can FLIP them: `data-mode="hero"` on `/`, `data-mode="rail"` elsewhere.
4. `Track`: `<main id="content" tabindex="-1" data-current="{slug}">` containing **all six** `<section>` pages in order (index, achievements, projects, experience, about, say-hi). Each section has `id="page-{slug}"`, `data-page="{slug}"` and `aria-labelledby` pointing at its title.
5. `Footer` (`<footer>`).

Hidden pages:
- The five non-current sections carry `inert` and are hidden by CSS: `.page[inert] { display: none; }` in Phase 3. No `hidden` attribute, so Phase 4 can switch to the transform track by overriding one rule under a script-set `html[data-js]` flag, without changing markup.
- With JS off a route therefore shows only its own page; header, footer, letter and rail links navigate between routes like a normal site.
- Section and element identity is the same on every route. Only `data-current`, `inert`, the title's heading level and `aria-current` differ.
- Images in non-current sections use `loading="lazy"`; the current section's image uses `loading="eager"`, so a route fetches only its own photo.

Headings:
- The current page's title is an `h1`; the five hidden pages' titles are `h2` (server-rendered per route).
- Index: visually hidden title "Yahya Hallani" (the wordmark is the nav, not the heading).
- Achievements: visually hidden "Achievements" plus the `aria-hidden` letter rows. About: visually hidden "Two habits" plus the `aria-hidden` TWO/HAB/ITS rows. Projects: visually hidden "Projects"; "Facturo" is one level below. Experience: visually hidden "Experience"; "Work" and "Involvement" are one level below. Say hi: visually hidden "Say hi".

URLs: `/`, `/achievements/`, `/projects/`, `/experience/`, `/about/`, `/say-hi/`, with trailing slash (design doc §2). Set `trailingSlash: true` in `next.config.ts` so the export emits `{route}/index.html` and every internal href and canonical uses the trailing slash.
