  <behavior>
    state.ts types:
    - `export type GamePhase = "ready" | "loading" | "playing" | "exited" | "error" | "fallback";`
    - `export interface GameState { readonly phase: GamePhase; readonly pct: number | null; readonly muted: boolean; }`
    - `export type GameIntent = { readonly type: "play" } | { readonly type: "progress"; readonly cur: number; readonly total: number } | { readonly type: "ready" } | { readonly type: "escape" } | { readonly type: "exit" } | { readonly type: "error" } | { readonly type: "retry" } | { readonly type: "mute" };`
    Cases:
    - initialState(true) -> { phase: "ready", pct: null, muted: false }; initialState(false) -> phase "fallback"
    - ready + play -> loading, pct null; exited + play -> loading
    - loading + progress(cur 37, total 100) -> pct 30 (floored to 10% steps); a second progress(39,100) returns the SAME object (toBe)
    - progressPct(cur,total) clamps to 0..100 and returns null for total <= 0 or non-finite input
    - loading + ready -> playing (pct kept); playing + mute -> muted true; again -> false
    - loading + exit -> exited; playing + exit -> exited, pct null, muted unchanged
    - loading + error -> error; playing + error -> error; error + retry -> loading, pct null
    - escape in any phase returns the same object (focus is a side effect in the controller)
    - fallback + any intent returns the same object; ready + exit/ready/progress/mute returns the same object
    protocol.ts:
    - `export type GameMsg = { readonly type: "progress"; readonly cur: number; readonly total: number } | { readonly type: "ready" } | { readonly type: "exit" } | { readonly type: "error" } | { readonly type: "escape" };`
    - `export type ParentMsg = { readonly type: "mute"; readonly value: boolean };`
    - readGameMsg returns null when frame is null, when e.origin !== window.location.origin, when e.source !== frame.contentWindow, when data is null/not an object/unknown type, when progress has non-finite cur/total or total <= 0 or cur < 0; returns a fresh object with only the known fields for valid messages (extra keys dropped)
    - Tests build MessageEvent via `new MessageEvent("message", { data, origin, source })` with a jsdom iframe appended to document.body
  </behavior>
